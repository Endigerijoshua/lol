# SIH26162 — AI-Based Detection of Industrial Fires & Persistent Thermal Sources

Smart India Hackathon 2026 (Software) entry. Uses **live NASA FIRMS satellite
hotspots** + **OpenStreetMap industrial & vegetation zones** + **WRI global
power plants** to flag fires near industry and track **persistent thermal
sources**, shown on a Leaflet map dashboard with a NASA GIBS true-color
satellite base-layer toggle. Classical geospatial logic + one weak-label
scikit-learn RandomForest (labels generated by our own spatial rule — no
hand-labelled data).

Tech: Python / FastAPI · Leaflet.js · SQLite · Shapely / GeoPandas · scikit-learn.

## Setup

1. Python 3.11+ required.
2. Install dependencies:

   ```
   python -m venv .venv
   .venv\Scripts\activate        # Windows
   pip install -r requirements.txt
   ```

3. Create `.env` from `.env.example` and set your NASA FIRMS MAP_KEY:
   (register free at https://firms.modaps.eosdis.nasa.gov/)

4. Run:

   ```
   uvicorn app.main:app --reload
   ```

5. Open http://localhost:8000 — API docs at http://localhost:8000/docs

### Warm the caches ahead of a demo

The OSM zone caches (industrial / vegetation / mining) are git-ignored and are
rebuilt from the Overpass API on first use. On a fresh checkout the *first*
dashboard load cold-builds them and can take a few minutes; the server also
refreshes missing caches in the background automatically at startup. For a
smooth demo, build them once in advance so the first page load is fast
(~10 s, FIRMS-bound):

```
python scripts/build_zone_caches.py
```

Re-running is a no-op while the caches are fresh (720 h TTL).

## Retraining the fire-type classifier

`fire_type_ml` comes from a weak-label RandomForest trained on our own
rule-based labels, wrapped in `CalibratedClassifierCV` (isotonic, cv=5) so the
served `fire_type_ml_confidence` is a calibrated probability, not a vote
fraction. Rebuild it (and its balance + calibration report) with:

```
python scripts/train_classifier.py
```

It always backfills 5 days of FIRMS history (the area API caps the day range at
[1..5]) to grow the training set, uses OSM + power-plant proximity as labels,
and refuses to write a model when any class is under 5% of the training set.
The `.pkl` stays git-ignored — training always regenerates it.
